# Google Cloud の同意画面を「本番環境」に公開する

いまは公開ステータスが「テスト」なので、**テストユーザーに入れたアカウントしか**「Googleでログインして同期を始める」を使えません。
「本番環境」にすると、Googleアカウントを持っている人なら誰でも同期を使えるようになります。

> この手順は、Google Cloud を管理しているアカウント（アプリ開発用のGmail）で行います。
> 仕事用や個人用のアカウントでログインしたままになっていないか、画面の右上で確認してください。

## 全体の流れ（6ステップ）

| | やること | 使う画面 | 目安 |
|---|---|---|---|
| 1 | プライバシーポリシーのページを公開する | GitHub Desktop・GitHub | 10分 |
| 2 | 問い合わせ先のメールアドレスを登録する | GitHub | 5分 |
| 3 | 「このドメインは自分のもの」とGoogleに証明する | GitHub・Google Search Console | 20分 |
| 4 | 同意画面に、ホームページとポリシーのURLを入れる | Google Cloud | 10分 |
| 5 | 「アプリを公開」を押す | Google Cloud | 1分 |
| 6 | ブランドの確認を受ける | Google Cloud | 数分〜3営業日 |

## 使うURL（コピーして使ってください）

| 項目 | 入れる値 |
|---|---|
| アプリのホームページ | `https://jeanjeanjean-sama.github.io/task-a-remind/` |
| プライバシーポリシー | `https://jeanjeanjean-sama.github.io/task-a-remind/privacy.html` |
| 承認済みドメイン | `jeanjeanjean-sama.github.io` |
| Search Console に登録するURL | `https://jeanjeanjean-sama.github.io/` |

---

## 1. プライバシーポリシーのページを公開する

1. GitHub Desktop で、変更されたファイルを確認し、「Commit to main」→「Push origin」を押します。
2. GitHub のリポジトリの「Actions」タブで、「Web版を公開」が緑のチェックになるまで待ちます（2〜3分）。
3. 次の2つをブラウザで開いて確認します。
   - https://jeanjeanjean-sama.github.io/task-a-remind/privacy.html が表示される
   - https://jeanjeanjean-sama.github.io/task-a-remind/ の画面のいちばん下に「プライバシーポリシー」のリンクがある

> ページの元は `src/privacy.html` です。直したら `npm run build` を実行して、`docs/privacy.html` も一緒にコミットします。

## 2. 問い合わせ先のメールアドレスを登録する

プライバシーポリシーには問い合わせ先が必要です。メールアドレスはリポジトリには書かず、GitHub の設定に入れます（公開されるページには表示されます）。

1. GitHub のリポジトリで「Settings」→「Secrets and variables」→「Actions」→「Variables」タブを開きます。
2. 「New repository variable」を押し、次のように入れて「Add variable」を押します。
   - Name：`CONTACT_EMAIL`
   - Value：アプリ開発用のGmailのアドレス
3. 「Actions」タブ →「Web版を公開」→「Run workflow」→ 緑の「Run workflow」を押して、公開し直します。
4. プライバシーポリシーの「10. 問い合わせ先」にメールアドレスが出ていれば完了です。

## 3. 「このドメインは自分のもの」とGoogleに証明する

Googleは、ホームページとポリシーが置いてある場所（`jeanjeanjean-sama.github.io`）が本当にあなたのものかを確認します。
確認用のファイルを `https://jeanjeanjean-sama.github.io/` の**いちばん上の場所**に置く必要があるので、そのための小さなリポジトリを1つ作ります（無料）。

### 3-1. 確認用のファイルを受け取る

1. [Google Search Console](https://search.google.com/search-console) を、**Google Cloud を管理しているアカウント**で開きます。
2. 「プロパティを追加」→ 右側の「**URL プレフィックス**」に `https://jeanjeanjean-sama.github.io/` を入れて「続行」を押します。
   （左側の「ドメイン」は使えません。github.io の設定を変える必要があるためです）
3. 「HTML ファイル」の方法を選び、`google〇〇〇〇.html` というファイルをダウンロードします。**この画面は閉じずに**おきます。

### 3-2. 確認用のリポジトリを作って、ファイルを置く

1. GitHub の右上の「＋」→「New repository」を押します。
2. Repository name に **`jeanjeanjean-sama.github.io`**（アカウント名と同じ。1文字も違わないように）と入れ、「Public」を選び、「Add a README file」にチェックを入れて「Create repository」を押します。
3. できたリポジトリで「Add file」→「Upload files」を押し、3-1 でダウンロードした `google〇〇〇〇.html` をドラッグして「Commit changes」を押します。
4. 「Settings」→「Pages」で、Source が「Deploy from a branch」、Branch が「main」「/ (root)」になっているか確認し、違っていれば直して「Save」を押します。
5. 1〜2分待って、`https://jeanjeanjean-sama.github.io/google〇〇〇〇.html` を開き、ファイルの中身（1行の文字）が表示されることを確認します。

> このリポジトリには、確認用のファイル以外は置かなくてかまいません。**確認用のファイルは消さないでください**（消すと確認が取り消されます）。
> たすかReマインドのWeb版（`/task-a-remind/`）は、これまでどおり開けます。

### 3-3. 確認する

1. Search Console の画面に戻り、「確認」を押します。
2. 「所有権を確認しました」と出れば完了です。

## 4. 同意画面に、ホームページとポリシーのURLを入れる

1. [Google Cloud コンソール](https://console.cloud.google.com/) で、たすかReマインドのプロジェクトを選びます。
2. 左のメニュー（≡）→「Google Auth Platform」→「**ブランディング**」を開きます。
3. 次のように入れます。

| 欄 | 入れる値 |
|---|---|
| アプリ名 | `たすかReマインド` |
| ユーザー サポートメール | アプリ開発用のGmail |
| アプリのロゴ | **最初は入れない**（入れると確認に時間がかかります。あとから足せます） |
| アプリケーションのホームページ | `https://jeanjeanjean-sama.github.io/task-a-remind/` |
| アプリケーションのプライバシー ポリシーのリンク | `https://jeanjeanjean-sama.github.io/task-a-remind/privacy.html` |
| アプリケーションの利用規約のリンク | 空欄のままでよい |
| 承認済みドメイン | 「ドメインを追加」→ `jeanjeanjean-sama.github.io` |
| デベロッパーの連絡先情報 | アプリ開発用のGmail |

4. 「保存」を押します。
5. 左のメニューの「**データアクセス**」を開き、登録されているスコープが次の2つ**だけ**であることを確認します。どちらも「機密性の高くない（非機密）スコープ」なので、動画の提出やセキュリティ審査はいりません。
   - `.../auth/drive.appdata`
   - `.../auth/userinfo.email`

   ほかのスコープ（`drive` や `drive.file` など）が入っていたら、削除して保存します。

## 5. 「アプリを公開」を押す

1. 左のメニューの「**対象**」を開きます。
2. 「公開ステータス：テスト」の下にある「**アプリを公開**」を押し、確認の画面で「確認」を押します。
3. 公開ステータスが「**本番環境**」になれば完了です。テストユーザーの登録は、もう必要ありません。

## 6. ブランドの確認を受ける

同意画面にアプリ名（たすかReマインド）を正しく表示するために、Googleの確認を受けます。

1. 「ブランディング」を開き、「**ブランディングを確認**」（Verify branding）を押します。
2. 自動の確認は、ふつう数分で終わります。
   - 「公開の準備ができました」と出たら、「**ブランディングを公開**」を押して完了です。
   - 問題が出たら、表示された理由を直して、もう一度「ブランディングを確認」を押します（下の「うまくいかないとき」を見てください）。
   - 自動で確認できないときは、人による確認（ふつう2〜3営業日）を申し込めます。結果は「デベロッパーの連絡先情報」のメールに届きます。

## 7. 動くか確かめる

1. ブラウザの**シークレット（プライベート）ウィンドウ**で https://jeanjeanjean-sama.github.io/task-a-remind/ を開きます。
2. 「設定」→「Googleでログインして同期を始める」を押し、**テストユーザーに入れていない**Googleアカウントでログインします。
3. ログイン画面にアプリ名と、許可の内容（このアプリ専用のデータ・メールアドレス）が出て、同期が始まれば成功です。

## うまくいかないとき

| 困ったこと | 考えられる原因と直し方 |
|---|---|
| 「ドメインの所有権が確認されていません」 | Search Console で確認したアカウントが、Google Cloud のプロジェクトの「オーナー」か「編集者」になっているか確認します。違うアカウントで確認した場合は、正しいアカウントで 3 をやり直します。 |
| 「ホームページにプライバシーポリシーへのリンクがありません」 | Web版のいちばん下にリンクが出ているか確認します。出ていなければ、Actions の「Web版を公開」が成功しているか確認します。 |
| 「ホームページがアプリを説明していません」 | Web版のいちばん下の説明文（`build.mjs` の `PAGES_FOOT`）を詳しくして、公開し直します。 |
| github.io が「共有のドメイン」だとして認められない | 人による確認で、独自のドメインを求められることがあります。独自ドメインは年に1,000〜2,000円ほどかかり、無料の範囲を超えるため、その場合は進め方を相談してください。 |
| 「このアプリは Google で確認されていません」という画面が出る | 非機密ではないスコープが入っている可能性があります。4 の 5 でスコープを確認します。 |
| ログイン画面にアプリ名ではなくドメイン名が出る | ブランドの確認（6）が終わっていない可能性があります。 |

## 公開したあとに気をつけること

- **スコープ（許可の種類）を増やすときは、先にプライバシーポリシーを直します。** 家族共有の機能で `drive.file` を足すときは、`src/privacy.html` の「3. Googleアカウントのデータの扱い」に書き足し、公開してから Google Cloud に追加します（自動テストが、`src/drive-sync.js` の権限がポリシーに書かれているかを確認します）。
- プライバシーポリシーを大きく変えたときは、上の制定日の下に「改定日」を書き足します。
- アプリ名・ロゴ・URLを変えると、もう一度ブランドの確認が必要になります。
