# Googleドライブ同期の設定（管理する人向け・最初に1回）

かんたん版（Web版）で「Googleでログインして同期」を使えるようにするための設定です。**Google Cloud の「OAuthクライアントID」を1つ作り、リポジトリに登録するだけ**です。費用はかかりません。

利用者向けの説明は [01_かんたん版の公開と使い方.md](01_かんたん版の公開と使い方.md#パソコンとスマホで同じデータを使うgoogleドライブ同期) にあります。

## しくみ（確認用）

| 項目 | 内容 |
|---|---|
| 保存先 | 利用者自身のGoogleドライブの「アプリ専用フォルダ（appDataFolder）」。ドライブの画面には表示されない、このアプリだけが読み書きできる場所 |
| 求める権限 | `drive.appdata`（このアプリ専用フォルダだけ）と `email`（どのアカウントで同期しているか表示するため）。**ドライブのほかのファイルは見えません** |
| 権限の分類 | どちらもGoogleの分類で「非センシティブ」。センシティブ・制限付きの権限で必要になる厳しい審査の対象ではありません |
| 開発・運営側が持つもの | クライアントID（公開しても問題のない識別番号）だけ。**利用者のデータやログイン情報は一切受け取りません** |
| ログインの合言葉 | Googleが発行するアクセストークン（約1時間有効）を、利用者のブラウザのタブの中だけに保存 |

## 1. Google Cloud でプロジェクトを作る

1. 管理用のGoogleアカウントで [Google Cloud Console](https://console.cloud.google.com/) を開く
2. 上部のプロジェクト選択 →「新しいプロジェクト」→ 名前：`tasuka-remind` →「作成」

## 2. Google Drive API を有効にする

1. 左上のメニュー →「APIとサービス」→「ライブラリ」
2. 「Google Drive API」を検索 →「有効にする」

## 3. 同意画面（ログインのときに表示される画面）を設定する

1. 「APIとサービス」→「OAuth 同意画面」（「Google Auth Platform」と表示される場合もあります）→「開始」
2. アプリ情報
   - アプリ名：`たすかReマインド`
   - ユーザーサポートメール：管理用のメールアドレス
3. 対象：**外部**
4. 連絡先のメールアドレスを入れて、ポリシーに同意して「作成」
5. 「データアクセス」→「スコープを追加または削除」で、次の2つを追加して保存
   - `.../auth/drive.appdata`
   - `.../auth/userinfo.email`（または `email`）
6. 「ブランディング」で、アプリのホームページに公開先のURL（例：`https://〇〇.github.io/tasuka-remind/`）、プライバシーポリシーのURL（下の「プライバシーポリシー」参照）を入れる

### 公開ステータスについて

- 作った直後は「テスト」状態です。この状態では、「対象」→「テストユーザー」に追加したGoogleアカウント（100人まで）だけがログインできます。**まずは自分と家族のアカウントを追加して試してください**
- 広く使ってもらうときは「対象」→「アプリを公開」で「本番環境」にします。非センシティブな権限だけなので、厳しい審査は不要です。ただしアプリ名やロゴを表示するには、Googleによるブランドの確認が行われることがあります。画面の案内に従ってください

## 4. OAuthクライアントIDを作る

1. 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
2. アプリケーションの種類：**ウェブ アプリケーション**、名前：`tasuka-remind web`
3. **承認済みの JavaScript 生成元**に次を追加
   - `https://〇〇.github.io`（GitHub Pagesの公開先。末尾の `/tasuka-remind/` は付けない）
   - `http://localhost:8080`（手元で `npm run serve` して試す場合）
4. 「承認済みのリダイレクト URI」は空のままでかまいません
5. 「作成」→ 表示された **クライアントID**（`〜.apps.googleusercontent.com`）をコピー

「クライアント シークレット」は使いません。リポジトリにも入れないでください。

## 5. リポジトリに登録する

**方法A：GitHubの変数に登録する【推奨】**

1. リポジトリの「Settings」→「Secrets and variables」→「Actions」→「Variables」タブ
2. 「New repository variable」
   - Name：`GOOGLE_CLIENT_ID`
   - Value：コピーしたクライアントID
3. 「Actions」→「Web版を公開」→「Run workflow」で公開し直す

公開のたびに、この値が自動でWeb版に入ります。フォーク（ほかの人がリポジトリを複製したもの）には引き継がれないので、ほかの人が同じIDを使ってしまうこともありません。

**方法B：ファイルに書く**

`src/config.json` の `googleClientId` に書いて、`npm run build` してコミットします。自分でサーバーに置く場合などに使います。

## 6. 確かめる

1. 公開先のWeb版を開き、「設定」→「Googleドライブで同期」→「Googleでログインして同期を始める」
2. テストユーザーに追加したアカウントでログインできること
3. 別の端末（またはシークレットウィンドウ）で同じアカウントでログインし、同じデータが見えること

## プライバシーポリシー

同意画面に載せるプライバシーポリシーには、少なくとも次のことを書きます（リポジトリの `SECURITY.md` の内容を元に、公開用のページを用意してください）。

- 保存するのは、利用者が入力した子どもの情報で、保存先は利用者自身のGoogleドライブのアプリ専用フォルダと、利用者の端末だけであること
- 開発・運営側は、利用者のデータ・メールアドレス・ログイン情報を受け取らず、保存もしないこと
- メールアドレスは、画面に「どのアカウントで同期しているか」を表示するためだけに使うこと
- 同期をやめる方法と、ドライブのデータを消す方法

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 設定画面に「まだ同期が使えるように設定されていません」と出る | クライアントIDが入っていません。手順5のあと、公開し直したか確認 |
| ログイン画面で「エラー 400: redirect_uri_mismatch」「origin_mismatch」 | 手順4の「承認済みの JavaScript 生成元」に、公開先のURL（`https://〇〇.github.io`）が正しく入っているか確認 |
| 「アクセスをブロック：このアプリは… テスト中」 | そのアカウントがテストユーザーに入っていません（手順3）。または本番環境に公開する |
| ログイン画面が出ない | ブラウザがポップアップをブロックしていないか確認 |
