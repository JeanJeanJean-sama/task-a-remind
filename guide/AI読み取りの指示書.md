# たすかReマインド：書類の読み取りの指示書

> 取り込み用ファイル 第1版／データ定義 第2版。この指示書は、アプリの定義（src/schema.json・src/templates.json）から自動で作られます。アプリを更新したら、指示書も書き出し直してください。

## 使う人へ（AIに渡す前に読んでください）

- この指示書と、読み取りたい書類（スキャンしたPDFや写真）を、**あなたが自分で使っているAI**（チャットのAI）に渡します。AIが作った答えを、たすかReマインドの「設定」→「読み取ったデータを取り込む」に貼り付けます。
- **たすかReマインドは、書類も入力した情報も、AIに送りません。** AIに渡すかどうか・何を渡すかは、あなたが決めます。AIとのやりとりは、そのAIのサービスの決まりに従います。
- AIに渡す前に、**受給者番号・保険証の番号・住所・名前**など、読み取りに要らないところを隠す（黒くぬる・切り取る）とよいです。
- AIの設定で、**会話をAIの学習に使わせないようにできるか**確かめてください。
- 取り込む前に、確認の画面で中身を1件ずつ見てください。番号の項目は取り込みません。AIは日付や名前を読み間違えることがあります。

---

## AIへ：あなたの役目

あなたの役目は、渡された書類（スキャンしたPDFや写真）を読んで、「たすかReマインド」（障害のある子どもや医療的ケアが必要な子どもの情報をまとめるアプリ）に取り込むための **JSON を1つ** 作ることです。

## 守ること

1. 書類に書いてあることだけを書く。推測で埋めない。読めない項目は書かない
2. 自信のない項目は、値を書いたうえで `"unclear"` にその項目の名前を入れる
3. 日付は西暦にする。日付の欄は `YYYY-MM-DD`、月の欄は `YYYY-MM`。和暦（令和・平成など）は西暦に直し、書類での書き方を `"memo"` に書く。日がはっきりしないときは、その日付の欄を書かず、分かる範囲を `"memo"` に書く
4. 「**過去の日付**」と書いた欄は、すでに起きたことの日付です。今日より後の日付にはなりません。未来の日付になったら、読み間違い（和暦の直し間違いなど）がないか見直す
5. **番号は書かない**：公費負担者番号・保険者番号、番号（受給者番号・記号番号など）、マイナンバー、保険証の記号・番号。書類に書いてあっても書かない
6. 子どもや家族の**名前・家の住所・生年月日**は書かない（病院や役所など、機関の住所・電話番号は書いてよい）
7. 選択肢のある項目は、下の選択肢の中から、書いてあるとおりの言葉で選ぶ。合うものがなければ「その他」
8. 下の表にない項目は書かない
9. 1つの書類から、いくつの記録を作ってもよい（例：入院の記録と、その病院の連絡先）
10. `"from"` には、書類のファイル名（ファイル名だけ。フォルダの名前は書かない）を入れる
11. `"madeOn"` には今日の日付を入れる
12. 答えは、JSON を1つだけ、コードブロック（```json 〜 ```）で出す。説明は、そのあとに短く

## ファイルの形

```json
{
  "format": "task-a-remind-import",
  "formatVersion": 1,
  "schemaVersion": 2,
  "madeBy": "読み取りに使ったAIの名前（任意）",
  "madeOn": "YYYY-MM-DD",
  "records": [
    {
      "type": "記録の種類",
      "from": "書類のファイル名",
      "data": {
        "項目": "値"
      },
      "unclear": [
        "自信のない項目"
      ],
      "memo": "ひとこと（任意）"
    }
  ]
}
```

- `format`・`formatVersion`・`schemaVersion` は、上のとおりに書く
- `records` の1件が1つの記録。`type` は下の「記録の種類」から選ぶ
- `data` には、項目の名前（英字）と値を書く。値はすべて文字（`"…"`）で書く
- `unclear`・`memo` は、なければ書かなくてよい

## 記録の種類と項目

### `visits`：受診・入院の記録

| 項目 | 意味 | 必須 | 形・選択肢 |
|---|---|---|---|
| `kind` | 種類 |  | 次から選ぶ：受診／入院／日帰り入院／検査／手術／診断／医療的ケアの開始・変更／事故・けが／セカンドオピニオン／発達の記録／その他 |
| `date` | 日付 | ○ | YYYY-MM-DD（**過去の日付**） |
| `endDate` | 終了日（入院など） |  | YYYY-MM-DD |
| `facility` | 病院・機関 |  | 短い文 |
| `department` | 診療科 |  | 短い文 |
| `doctor` | 担当医 |  | 短い文 |
| `summary` | 概要。一覧に出る短い説明。音声入力で話したままでもかまいません。 | ○ | 文章 |
| `symptoms` | 症状・経緯 |  | 文章 |
| `treatment` | 治療・検査の内容 |  | 文章 |

### `diagnoses`：診断名

| 項目 | 意味 | 必須 | 形・選択肢 |
|---|---|---|---|
| `name` | 診断名 | ○ | 短い文 |

### `contacts`：医療機関・関係機関

同じ病院で診療科が複数あるときは、診療科ごとに1件ずつ登録する（画面では病院ごとにまとめて表示）。

| 項目 | 意味 | 必須 | 形・選択肢 |
|---|---|---|---|
| `kind` | 種類 | ○ | 次から選ぶ：病院／療育／訪問看護／医療機器業者／福祉サービス／相談支援／保育園・学校／子育て支援／教室・親の会／役所／児童相談所／その他 |
| `name` | 機関の名前。例：○○こども病院 | ○ | 短い文 |
| `department` | 診療科・区分。例：循環器科、理学療法 |  | 短い文 |
| `person` | 主治医・担当者 |  | 短い文 |
| `phone` | 電話番号 |  | 電話番号 |
| `hours` | 受付時間。例：平日 9:00〜17:00 |  | 短い文 |
| `address` | 住所 |  | 文章 |
| `visitPattern` | 通院・利用のしかた。例：月1回、心臓の経過観察 |  | 文章 |
| `supplies` | 処方・診療材料 |  | 文章 |

### `profile`：子どもの情報

1項目1行。内容が変わったら古い行に「いつまで」を入れて残し、新しい行を追加する（履歴）。

| 項目 | 意味 | 必須 | 形・選択肢 |
|---|---|---|---|
| `category` | 分類 | ○ | 次から選ぶ：基本情報／特徴と関わり方／好きなこと・遊び／苦手なこと／食事／睡眠／身体・アレルギー／医療・服薬／発達・できること／出生時の様子／本人・家族の意向／その他 |
| `label` | 項目名。候補から選ぶか、自由に入力します。 | ○ | 短い文 |
| `value` | 内容 | ○ | 文章 |
| `caution` | 注意すること。例：首が弱いので支えが必要 |  | 文章 |
| `validFrom` | いつから |  | YYYY-MM-DD |
| `validTo` | いつまで。空欄＝今の情報。過去の情報になったら日付を入れる。 |  | YYYY-MM-DD |

### `process`：手続きを始める

届いた案内などから、これから行う手続きを始めるときに使います。`templateId` は下の「使える手続きの型」から選びます。

| 項目 | 意味 | 必須 | 形・選択肢 |
|---|---|---|---|
| `templateId` | 手続きの型 | ○ | 手続きの型の templateId（下の一覧から） |
| `deadline` | 締め切り | ○ | YYYY-MM-DD |
| `name` | 手続きの名前 |  | 短い文 |
