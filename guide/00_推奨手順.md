# 推奨手順：GitHubリポジトリでの管理とWeb版の公開

この手順書は、**開発・管理する人**向けです。利用者向けの手順は `01`（かんたん版）と `02`（Google版）にあります。

## 全体像

```
       開発する人                         GitHub                               利用者
┌──────────────────┐   push   ┌──────────────────────────────┐
│ src/ を直す        │ ───────▶ │ main ブランチ                  │
│ npm run build     │          │  ├ 自動テスト（Actions）        │
│ npm test          │          │  ├ Web版を自動公開 ───────────────▶ https://〇〇.github.io/tasuka-remind/
└──────────────────┘          │  └ タグ v0.2.0 → Releases ──────▶ GAS版のzip（管理者がスプレッドシートに反映）
                              └──────────────────────────────┘                    │
                                                                    配布用スプレッドシート（/copy リンク）──▶ 利用者
```

| 提供するもの | 置き場所 | 利用者への届け方 |
|---|---|---|
| Web版（かんたん版） | GitHub Pages（リポジトリから自動公開） | URLを伝える |
| Google版 | `gas/` の4ファイル → 配布用スプレッドシート | スプレッドシートの `/copy` リンクを伝える |
| ソースコード・手順書 | リポジトリ | ― |

---

## 1. はじめに決めること

### 1-1. リポジトリを「公開」にするか「非公開」にするか

| | 公開（Public）【推奨】 | 非公開（Private） |
|---|---|---|
| GitHub Pagesの公開 | 無料アカウントでできる | 有料プラン（GitHub Pro / Team など）が必要 |
| 見える人 | 誰でもコードを見られる | 招待した人だけ |
| 向いている場合 | 当事者コミュニティで改善していく | 社内だけで試す |

**公開リポジトリを推奨します。** このリポジトリに入るのはプログラムと手続きの型だけで、子どもの情報は入りません（データは各利用者の端末やGoogleドライブに保存されます）。

> 公開する前に、**ライセンス**（他の人がコードを使ってよい条件）を決めてください。今は `package.json` が `UNLICENSED`（無断利用不可）になっています。広く使ってもらいたい場合はMITライセンスなどを、GitHubの「Add file → Create new file → `LICENSE`」から追加できます。

### 1-2. 個人アカウントか、Organizationか

複数人で管理する予定があれば、GitHubの **Organization**（無料）を作り、その下にリポジトリを作ると、担当者の入れ替わりに強くなります。URLは `https://（Organization名）.github.io/tasuka-remind/` になります。

## 2. リポジトリを作って、最初のコードを入れる

### 2-1. GitHubでリポジトリを作る

1. GitHubにログインし、右上の「＋」→「New repository」
2. 設定する
   - Owner：自分、またはOrganization
   - Repository name：`tasuka-remind`
   - Public を選ぶ
   - 「Add a README」などのチェックは**すべて外す**（中身はこちらから入れるため）
3. 「Create repository」

### 2-2. 手元のコードを入れる

受け取った `tasuka-remind` フォルダには、**最初のコミットが済んだ状態のGit履歴**が入っています。フォルダの中でターミナルを開き、次を実行します（`〇〇` は自分のユーザー名またはOrganization名）。

```bash
cd tasuka-remind
git remote add origin https://github.com/〇〇/tasuka-remind.git
git push -u origin main
```

コマンドを使わない場合は、GitHub Desktop で「Add an Existing Repository」からこのフォルダを選び、「Publish repository」でも同じことができます。

### 2-3. 入ったか確かめる

- リポジトリのトップにREADMEが表示される
- 「Actions」タブで「テスト」が動き、緑のチェックになる（数分かかります）

---

## 3. Web版を公開する（GitHub Pages）

1. リポジトリの「Settings」→ 左の「Pages」
2. 「Build and deployment」の **Source** を「**GitHub Actions**」にする
3. 「Actions」タブ →「Web版を公開」→「Run workflow」→「Run workflow」
4. 数分待つと完了します。「Settings」→「Pages」の上部に表示されるURLが公開先です
   - 例：`https://〇〇.github.io/tasuka-remind/`
5. スマホでURLを開き、「サンプルで試す」で動くことを確かめる

**パソコンとスマホで同じデータを使えるようにする（Googleドライブ同期）**には、続けて [04_Googleドライブ同期の設定.md](04_Googleドライブ同期の設定.md) を行い、クライアントIDをリポジトリの変数 `GOOGLE_CLIENT_ID` に登録してから公開し直します。

これ以降は、**main に push するたびに、テストが通れば自動で公開されます**。テストが失敗すると公開されず、前の版がそのまま残ります。

> Web版は、利用者がホーム画面に追加するとアプリのように使えます。電波がなくても、一度開いたことがあれば起動できます。更新後は、次にネットにつながった状態で開いたときに新しい版になります。

## 4. 守りを固める（おすすめの設定）

| 設定 | 場所 | 理由 |
|---|---|---|
| mainを保護する | Settings → Rules → Rulesets →「New branch ruleset」。対象を `main` にし、「Require a pull request before merging」と「Require status checks to pass」（`test` を選ぶ）をオンにする | テストが通らない変更や、確認されていない変更が公開されるのを防ぐ |
| シークレットの検出 | Settings → Code security →「Secret Protection」「Push protection」をオン | DiscordのWebhook URLなどを誤ってコミットしたときに止める |
| Dependabot | 設定済み（`.github/dependabot.yml`） | 使っている部品の更新を月1回知らせる |
| Issueのラベル | Issues → Labels で「不具合」「要望」「手続きの型」を作る | テンプレートが自動でラベルを付ける |

**個人情報の事故を防ぐしくみ**も入っています。

- `.gitignore`：書き出したデータ（`たすかReマインド_データ_*.json`）、PDF、`.ics` はコミットされない
- 自動テスト：上のファイルがリポジトリに入っていると失敗する
- Issue・プルリクエストのテンプレート：個人情報を書かないよう、毎回表示する

## 5. ふだんの開発の流れ

```bash
git switch -c feature/手順書の写真    # 作業用のブランチを作る
# src/ を直す
npm run build                        # docs/ と gas/ を作り直す
npm test                             # テスト
npm run serve                        # http://localhost:8080 で画面を確認（任意）
git add -A && git commit -m "手順書に写真を付けられるようにする"
git push -u origin feature/手順書の写真
```

GitHubでプルリクエストを作り、テストが緑になったら main にマージします。マージすると、Web版は自動で公開されます。

**大事な決まり**

- 直すのは `src/` だけ。`docs/`・`gas/Index.html`・`gas/Shared.gs`・`guide/データ定義書.md` は `npm run build` で作られるファイルです。**作られたファイルも一緒にコミットします**（Google版の担当者がリポジトリから直接コピーできるようにするため）。作り直し忘れは自動テストが見つけます
- データ定義（`src/schema.json`）の項目の**名前を変える・消す**ときは、`schemaVersion` を上げ、`src/logic.js` の `migrate()` に変換を書きます（詳しくは `guide/データ定義書.md`）

## 6. バージョンを出す（リリース）

利用者に「新しい版です」と伝える単位です。Web版はmainにマージした時点で公開されますが、Google版はリリースごとに配布用スプレッドシートへ反映します。

1. `package.json` の `version` を上げる（例：`0.1.0` → `0.2.0`）
2. `CHANGELOG.md` に変更点を書く
3. `npm run build` → コミット → mainにマージ
4. タグを付けて push する
   ```bash
   git switch main && git pull
   git tag v0.2.0
   git push origin v0.2.0
   ```
5. 「Releases」に、次の2つのzipが自動で置かれます
   - `tasuka-remind-gas-v0.2.0.zip`：Google版の4ファイル
   - `tasuka-remind-web-v0.2.0.zip`：Web版一式（GitHub Pages以外に置きたいとき用）

バージョンの付け方の目安：

| 変更 | 例 |
|---|---|
| 不具合の修正だけ | 0.2.0 → 0.2.1 |
| 機能の追加 | 0.2.1 → 0.3.0 |
| データ定義の大きな変更（`schemaVersion` が上がる） | 0.3.0 → 0.4.0（1.0になってからは 1.x → 2.0） |

## 7. Google版を配布・更新する

### 7-1. 最初の配布用スプレッドシート

`guide/02_Google版の導入手順.md` の「A. 配布用のスプレッドシートを作る」のとおりに作り、`/copy` リンクをREADMEや案内ページに載せます。

**配布用スプレッドシートは、管理者の共有アカウントで持つ**のがおすすめです（担当者個人のアカウントだと、異動や退職のときに困るため）。

### 7-2. 新しい版を反映する

**方法A：手で貼り付ける（かんたん）**

1. Releases から `tasuka-remind-gas-v〇〇.zip` をダウンロードして開く
2. 配布用スプレッドシートの「拡張機能」→「Apps Script」で、4ファイルの中身を置き換えて保存
3. 配布用スプレッドシートで「① 初期設定」を実行し、エラーが出ないことを確かめる

**方法B：clasp を使う（コマンドに慣れている人向け）**

```bash
npm install -g @google/clasp
clasp login                          # ブラウザでGoogleにログイン
cp .clasp.json.example .clasp.json   # scriptId を配布用スプレッドシートのものにする
npm run gas:push                     # ビルドして gas/ をアップロード
```

`scriptId` は、Apps Scriptの「プロジェクトの設定」→「ID」で確認できます。`.clasp.json` は人ごとに違うので、コミットしません（`.gitignore` 済み）。

### 7-3. すでに使っている利用者への案内

コピー済みのスプレッドシートは自動では更新されません。新しい版を使ってもらうときは、次のように案内します。

1. 今のアプリで「設定」→「データを書き出す」（ドライブに保存されます）
2. 新しい配布用リンクから、スプレッドシートをコピーし直す → 初期設定 → Discordの設定 → Webアプリを出す
3. 新しいアプリで「設定」→「書き出したデータを読み込む」

利用者が増えてこの作業が負担になってきたら、GASの「ライブラリ」機能で、コードだけを一か所から更新する方式に切り替えます（`guide/03_設計メモ.md`）。

## 8. 困ったとき

| 症状 | 対処 |
|---|---|
| Actionsの「テスト」が赤い | 失敗したステップを開いてメッセージを読む。「docs/ や gas/ が src/ と合っていません」なら、手元で `npm run build` してコミット |
| Web版が更新されない | 「Actions」→「Web版を公開」が緑か確認。スマホでは一度アプリを閉じて開き直す |
| Pagesの設定に「GitHub Actions」が出ない | リポジトリが非公開で、無料プランの可能性。公開にするか、有料プランにする |
| 404になる | URLの末尾（リポジトリ名）が合っているか確認。公開直後は数分かかることがある |
| リリースのzipができない | タグ名と `package.json` の version が同じか確認（`v0.2.0` と `0.2.0`） |
