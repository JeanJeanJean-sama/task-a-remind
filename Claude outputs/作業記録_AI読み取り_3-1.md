## 3. checkImport の結果の形（3-2 の確認の画面で使う）

`Logic.checkImport(data, schema, db, templates, { childId, today })` は、`records` と同じ順の配列を返す。保存はしない。**子どもを選び直したら、もう一度呼ぶ**（生まれる前の日付・重なりは子どもごとに違う）。

```js
{
  index: 0,                 // records の何件目か（0から）
  type: 'visits',           // records[].type
  label: '受診・入院の記録', // 画面に出す種類の名前（process は「手続きを始める」）
  rec: { ... },             // 保存する値（定義にある項目だけ。初めの値・sourceFile も入っている）
  from: '2026-03-10_….pdf',  // 元の書類（フォルダの名前は落とす）
  memo: '…',                // AIからのひとこと
  unclear: ['date'],        // AIが自信がない項目（rec にあるものだけ）
  dropped: [{ key, reason }], // 捨てた項目。reason: number（番号）/ unknown（定義にない）/ auto（childId・sourceFile など自動で入る）/ badValue
  defaulted: ['visibility'],  // 初めの値を入れた項目（process は生年月日から入れた deadline）
  problems: [{ level, code, key, message }],
  duplicateOf: null | { col, id, index, text },
                            // 今のデータと重なる：col・id が入り index は -1
                            // ファイルの中の前の記録と重なる：index にその件数目、col・id は空
                            // text は画面に出す説明（例：「2025-05-01 〇〇病院」）
  certificateId: '',        // process だけ：型の受給者証の種類に合うものが1つなら、そのID（画面で選び直せる）
  canImport: true,          // block の問題がなければ true。false ならチェックできないようにする
  checked: true             // 最初のチェック。canImport で、warn の問題がないときだけ true
}
```

### problems の level と code

| level | 意味 | code |
|---|---|---|
| `block` | 取り込めない | `badType`（使えない種類）、`noData`（data がない）、`wareki`（和暦が残っている）、`badDate`（形が YYYY-MM-DD／YYYY-MM でない・ない日）、`noTemplate`（process の型がない）、`required`（process の型・締め切りがない） |
| `warn` | 印を付けて最初はチェックを外す | `unclear`、`notInOptions`（選択肢にない値。certificates の templateId がない型もここ）、`required`（必須の項目がない）、`future`（未来の日付）、`beforeBirth`（生まれる前の日付）、`duplicate`（同じものがありそう） |
| `info` | 知らせるだけ | `numberDropped`（番号の項目を捨てた）、`deadlineFromBirth`（締め切りを生年月日から入れた） |

`key` は問題のある項目の名前（項目によらないものは空）。画面では、項目の横に印を出すのに使える。`message` はそのまま画面に出せるやさしい文。

### 保存

`Logic.applyImport(items, childId, templates, today, { db })` は、`checked` かつ `canImport` のものだけを `[{ col, rec }]` にする（`saveMany()` にそのまま渡せる形）。ID・作成日時・更新日時・`deleted: false`・`childId` を付ける。`profile` は今のいちばん下の並び順にする。`process` は `planProcess()` で工程のタスクにし、`item.certificateId` を受給者証に、同じファイルで取り込む医療機関・関係機関も工程の連絡先に使う。

画面でのチェックの付け外しは、`item.checked` を書き換えて `applyImport` に渡せばよい。

## 4. 3-1 の中で仮に決めたこと（Jean=Summer に確かめてほしい）

1. **重なりの見分け方**（提案書 6-4、未決）
   - 受診・入院：同じ子どもで、日付と病院の名前が同じ（空白・全角半角のちがいは見ない。病院が両方空でも同じとみなす）
   - 医療機関：名前が同じで、診療科が同じか、どちらかが空（診療科ごとに1件ずつ登録する決まりのため）
   - 成長の記録：できたことが同じ／診断名：名前が同じ
   - 受給者証：種類と有効期限が同じ（両方空も同じ）
   - 子どもの情報：分類・項目名・内容がすべて同じ
   - 手続き：同じ型の未完了の工程がある（もう始まっている）
   - ファイルの中で同じものが2回出てきたら、2つ目以降に印
   - ほかの子どもの記録・削除済みの記録とは比べない
2. **どの欄に「過去の日付だけ」を付けるか**：上の表。visits.endDate は付けなかった
3. **生まれる前の日付を調べる欄**：「過去の日付だけ」の欄だけ（有効期限・締め切りは調べない）
4. **月の欄（diagnosedOn）**：`YYYY-MM` だけを受け付ける。`YYYY-MM-DD` も「形が壊れている」で取り込めない（TRMが直さない、に合わせた）
5. **全角の数字**の日付（２０２１-０２-２８）は半角にして受け付ける（和暦の変換ではないため）
6. **初めの値**：入っていない項目には、ふだんの入力と同じ初めの値を入れる（例：visits.kind は「受診」、見せてよい範囲）。ただし**必須の項目には入れない**（推測で埋めないため。certificates.kind がなければ `required` の印）。子どもの情報の見せてよい範囲は、分類ごとの決まり（categoryVisibility）に合わせる
7. **取り込まない項目**：番号（number・issuerNumber）のほか、画面に出ない項目（childId・order など）、つながり（ref）、`sourceFile`（`from` から入れる）。`note`（メモ）は取り込む（定義にある項目のため）
8. **元の書類**：`from` はファイル名だけを残し、フォルダの名前は捨てる（パスに利用者の名前が入ることがあるため）
9. **選択肢にない値**は、利用者がチェックすれば、そのまま保存する（「その他」に置き換えない）
10. **手続き**：型・締め切りがなければ取り込めない。締め切りがなくても、型に「生年月日から決める」があれば入れる（`info`）。締め切りが過去でも印は付けない（工程は今日以降に詰まる）
11. 取り込み用ファイルの `schemaVersion` がアプリより新しい、`formatVersion` が 2 以上なら「アプリを更新してください」
